# 开新店资料审核锁定页设计

## 背景

登录后选择“开新店”时，当前流程会直接准备草稿门店并进入门店资料页。新流程需要先展示一个与消息详情页一致的锁定画面，明确提示用户必须提交审核资料，用户点击操作按钮后再进入审核资料页面。

## 目标

- 新增一个可复用的开新店资料审核锁定组件。
- 锁定组件复用 `src/pages/dashboard/message-detail/index.vue` 的自定义导航栏、浅灰背景、白色内容区和主操作按钮布局。
- 将审核资料页路径作为参数传入组件，避免组件绑定尚未创建的具体页面。
- 将 `store-access-scope.vue` 的“开新店”流程接入锁定页。
- 当前使用已有的 `/pages/me/store-info/index?mode=create` 作为临时审核资料入口，未来审核资料页完成后只替换路径参数。

## 非目标

- 本次不新增真正的审核资料页面。
- 不修改消息详情页的展示和消息动作逻辑。
- 不修改门店审核接口或后端状态流转。

## 设计

### 组件

新增 `src/components/store-create-lock/store-create-lock.vue`。

组件接收一个必填的 `auditPagePath` 属性，值为完整的 uni-app 页面路径，可包含 query 参数。组件只负责展示锁定内容和触发导航，不负责创建门店或加载审核数据。

文案固定为：

- 页面标题：`开新店`
- 内容标题：`开新店前请先提交审核资料`
- 内容正文：`为保障门店信息真实有效，开设新分店前需要先填写并提交门店资料。审核通过后，即可进入新店经营管理。`
- 操作按钮：`去提交审核资料`

点击操作按钮时调用 `uni.navigateTo({ url: auditPagePath })`。当路径为空或页面跳转失败时，显示“审核信息页面暂未配置”，避免出现无反馈点击。

组件使用 `back-button` 返回上一级页面，并保持与消息详情页相同的页面内容比例、间距、颜色和按钮交互反馈。

### 路由承载页

新增 `src/pages/me/store-create-lock/index.vue` 作为组件的路由承载页。承载页负责读取路由参数并把审核资料路径传给组件，组件本身不作为 uni-app 路由目标。

承载页接收：

- `auditPath`：经过 URL 编码的审核资料页面路径；未传入时使用当前临时路径。
- `storeId`：当前草稿门店 ID，用于构造临时审核资料路径。

当前临时路径为 `/pages/me/store-info/index?mode=create&storeId={storeId}`。未来审核资料页创建后，由调用方传入新的 `auditPath`，无需修改锁定组件。

### 开新店流程

`store-access-scope.vue` 继续通过已有的 `create-store` 事件通知登录页并关闭弹窗。登录页的 `handleCreateStore` 继续复用现有草稿门店查找/创建逻辑，成功取得 `storeId` 后不再直接进入门店资料页，而是跳转到锁定页，并把临时审核资料路径编码后作为 `auditPath` 传入。

流程如下：

```text
登录成功
  -> 展示可访问范围
  -> 点击“开新店”
  -> 查找或创建草稿门店
  -> 进入开新店资料审核锁定页
  -> 点击“去提交审核资料”
  -> 跳转 auditPath 指定页面
```

### 错误处理

- 草稿门店查找或创建失败：沿用现有错误日志和 toast，不进入锁定页。
- `auditPath` 为空：按钮点击后显示未配置提示。
- `uni.navigateTo` 失败：显示未配置提示；锁定页保持可见，用户可以返回或重试。

## 验证

- 先为路径构造/解析行为补充可执行测试，并确认测试在实现前按预期失败。
- 运行 `pnpm type-check` 和 `pnpm lint`。
- 运行 `pnpm build:h5:test`，确认新增页面能够被 uni-app 路由发现。
- 使用 H5 页面验证：登录后点击“开新店”进入锁定页；点击“去提交审核资料”进入临时门店资料页；返回按钮可回到登录页。
- 检查桌面端和移动尺寸下锁定页无空白、溢出或文字遮挡，且控制台没有新增错误。
